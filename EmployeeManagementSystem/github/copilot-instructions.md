# Project rules — Employee Management System (training project)

- No LINQ anywhere in this project, ever.
- This is a learning project: every required language concept should be the 
  natural solution to a real feature, not a standalone demo method. If a 
  concept genuinely has no organic use case in the current phase, isolate it 
  in a clearly labeled method and say so honestly in a comment — don't force 
  an artificial use case.
- You (the AI) have creative and architectural freedom over class design, 
  naming, and structure. Requirements are fixed; execution is yours to design.
- Comments should explain real engineering tradeoffs at decision points, not 
  narrate what the code does line by line.
- Stay within the current phase's scope — don't implement functionality 
  belonging to a later phase even if it seems related.
- After generating code, briefly explain your design reasoning: what you 
  chose to model/build and why, and any tradeoffs made.
